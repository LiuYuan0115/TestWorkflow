# 测试设计方法论参考

## 一、测试点四分类（建模前置）

在建模前，先判断每个测试点属于哪类，类型决定后续选什么模型、用什么设计方法。

| 类型 | 特征 | 建模方式 | 设计方法 |
|------|------|---------|---------|
| 流程类 | 有步骤和分支，不同输入走不同路径，可绘成流程图 | 流程图 / 状态机图 | 路径分析法 |
| 参数类 | 参数取值有限，不同值对应不同处理或响应 | 输入-输出表 | 逐行覆盖 |
| 数据类 | 数据为取值范围，范围内处理相同 | 等价类分析表 | 等价类 + 边界值 |
| 组合类 | 多因素叠加影响结果 | 因子表 + 流程图 | 正交分析 |

**区分口诀：**
- 流程类 = 能画"输入→判断→动作→…"的图
- 参数类 vs 数据类 = 值是离散且每个值处理不同 → 参数类；值是连续范围且处理相同 → 数据类
- 组合类 = ≥2 个独立因素互相影响

## 二、四步测试设计法

```
建模 → 基础用例 → 数据补充 → 扩展
```

### 2.1 建模

按测试点类型建模：
- 流程类 → Mermaid 流程图或状态机图
- 参数类 → 输入-输出表（参数 + 取值 + 约束 + 预期输出）
- 数据类 → 等价类分析表（条件 + 有效等价类 + 无效等价类）
- 组合类 → 因子表（因子 + 各水平取值）

### 2.2 基础用例（路径覆盖策略）

**流程类路径覆盖策略选择：**

| 策略 | 做法 | 覆盖力 | 适用场景 |
|------|------|--------|---------|
| 分支覆盖 | 每个判定 True/False 至少各一次 | 中 | 低风险次要流程 |
| 最小线性无关覆盖 | 每个路径片段至少一次 | 较强 | **默认**，常规流程 |
| 全覆盖 | 所有可能路径 | 最强 | 高风险核心流程 |

**选策略原则：**
- 风险等级"高" → 全覆盖
- 风险等级"中" → 最小线性无关覆盖
- 风险等级"低" → 分支覆盖

**参数类：** 输入-输出表每行至少一条用例（100% 覆盖）。

**数据类：** 每个等价类至少一条用例，边界值在数据补充阶段注入。

**组合类：** 用正交表覆盖多因子多水平组合，剔除无效约束组合。

### 2.3 数据补充

| 方法 | 做什么 | 示例 |
|------|--------|------|
| 等价类划分 | 有效等价类 + 无效等价类 | 有效：1~100；无效：0、101、字母 |
| 边界值分析 | 刚好等于、刚刚大于、刚刚小于边界 | 边界 1 和 100 → 测 0、1、2、99、100、101 |

**边界值必须精确到具体数字**，不能写"输入负数"，要写"-1"。

### 2.4 扩展（错误推测 + 非功能）

- 错误推测：特殊字符、空值、重复提交、网络中断、超时、并发冲突
- 非功能：兼容性（多端/多浏览器）、性能（大数据量/并发）、安全（越权/注入）

## 三、六质量属性（全面性扫描）

| 属性 | 关注点 | 常见测试类型 |
|------|--------|-------------|
| 功能性 | 正确性、安全性、兼容性 | 功能测试、安全测试、兼容性测试 |
| 可靠性 | 成熟性、容错性、可恢复性 | 稳定性测试、异常测试、恢复测试 |
| 易用性 | 易理解、易操作、界面 | 用户体验测试 |
| 效率 | 时间特性、资源利用 | 性能测试、压力测试 |
| 可维护性 | 易分析、易修改 | 代码审查、单元测试 |
| 可移植性 | 适应性、易安装 | 平台兼容测试 |

## 四、量化门禁指标

| 指标 | 合格线 | 不达标后果 |
|------|--------|-----------|
| 测试点覆盖率 | ≥95% | 必须补充 |
| 反向/异常用例占比 | ≥30% | 警告 |
| 边界值覆盖 | 100%（每个等价类至少一条） | 必须补充 |
| 重复用例率 | ≤10% | 警告 |
| 优先级分布 | P0≥1，P0+P1≥40% | 警告 |
| 高危场景覆盖 | 见下方 8 类 | 必须补充 |

## 五、高危场景 8 类核查清单

| # | 场景 | 检查什么 | 适用范围 |
|---|------|---------|---------|
| H1 | 权限互斥 | 越权访问、角色切换后权限残留 | 所有涉及权限的功能 |
| H2 | 并发冲突 | 多设备同时操作、同一资源同时修改 | 共享资源、写操作 |
| H3 | 弱网/离线 | 2G/3G、飞行模式、网络切换、超时重试 | 移动端、网络敏感功能 |
| H4 | 非法输入 | SQL 注入、XSS、特殊字符（`<>&"'`）、超长字符串 | 所有用户输入 |
| H5 | 接口安全 | 参数篡改、重放攻击、Token 过期 | API 接口 |
| H6 | 数据一致性 | 操作中断后状态回滚、缓存与数据库不一致 | 写操作、分布式 |
| H7 | 资源耗尽 | 内存泄漏场景、无限递归、文件句柄不释放 | 长时间运行、循环操作 |
| H8 | 时间相关 | 时区切换、过期时间边界、定时任务重叠 | 有时间逻辑的功能 |

**判断适用性：**
- Web 前端 → H1、H3、H4、H8 必须覆盖
- API 后端 → H1、H2、H4、H5、H6、H8 必须覆盖
- 移动端 → H1、H3、H7、H8 必须覆盖

## 七、自检清单（阶段 5 使用）

**量化指标检查：**
- [ ] 测试点覆盖率 ≥95%（对照 _analysis.md 测试点清单逐一映射）
- [ ] 反向/异常用例占比 ≥30%
- [ ] 每个等价类至少一条边界值用例（边界值精确到具体数字）
- [ ] 重复用例率 ≤10%
- [ ] P0 至少 1 条，P0+P1 合计 ≥40%

**高危场景检查：**
- [ ] 根据功能类型确定适用的高危场景类别（见第五节）
- [ ] 逐类检查是否有对应用例，缺失的标注并补充

**基础检查：**
- [ ] 每个功能点有正常 + 异常场景
- [ ] 登录/支付/权限类功能有安全场景
- [ ] 用例步骤 2-7 步，预期结果 1-5 个
