# /testcase-ui-enhance — UI 测试用例步骤描述优化

## 触发场景

用户运行 `/testcase-ui-enhance` 或提到"优化 UI 测试用例步骤"、"补充元素特征"、"完善位置上下文"时激活。

## 配置读取

启动时执行：
1. 用 `Bash` 运行 `pwd` 获取工作目录，记为 `$WORKDIR`，后续所有文件路径均拼接为绝对路径

## 输入方式

### 直接模式（带参数）

```
/testcase-ui-enhance testing/ui-testcases/
/testcase-ui-enhance testing/ui-testcases/chat-ui.yml
/testcase-ui-enhance --module chat-ui
```

参数说明：
- `<目录路径>`：扫描该目录下所有 `.yml` 文件（排除 `index.yml`）
- `<文件路径>`：直接处理指定 YAML 文件
- `--module <模块名>`：处理 `testing/ui-testcases/<模块名>.yml`

### 交互模式（无参数）

无参数时，用 `AskUserQuestion` 引导用户选择：

```
请选择要优化的测试用例来源：
  [1] 指定目录 —— 批量处理目录下所有 .yml 文件
  [2] 指定文件 —— 处理单个 YAML 文件
  [3] 按模块名 —— 自动定位 testing/ui-testcases/<模块>.yml
```

选 [1] 时，提示输入目录路径。
选 [2] 时，提示输入文件路径。
选 [3] 时，列出 `testing/ui-testcases/` 下所有模块供选择。

## 执行流程

### 步骤 1：扫描分析

根据输入定位目标文件：
- 目录路径：用 `Bash` 运行 `find <目录> -name "*.yml" ! -name "index.yml"` 列出所有文件
- 文件路径：直接读取该文件
- `--module`：定位 `$WORKDIR/testing/ui-testcases/<模块名>.yml`

若文件不存在，提示错误并终止：
```
❌ 未找到文件：<路径>
请先运行 /testcase-ui-generate 生成 UI 测试用例文件。
```

读取所有目标文件，统计并输出扫描结果：
```
扫描完成：
· 文件数：<N> 个
· 用例数：<M> 个
· 步骤数：<K> 步（待评分）
```

### 步骤 2：质量评分

对每个用例的每个步骤进行评分，基础分 100，按以下规则扣分：

| 规则 | 扣分 | 问题标签 |
|------|------|----------|
| 描述 < 10 字符 | -20 | 描述过短 |
| 不含元素类型关键词（按钮/输入框/链接/图标/文本/标签/下拉/复选/单选/开关） | -30 | 缺少目标元素类型 |
| 不含位置上下文（位于/在...的/顶部/底部/左侧/右侧/上方/下方/页面/区域/弹窗/对话框） | -20 | 缺少位置上下文 |
| 不含视觉特征（颜色词/图标/文字内容引用/占位符文本） | -15 | 缺少视觉特征 |
| 纯模糊词（"点击它"/"输入"/"等待"/"操作"/"处理"/"执行"） | -40 | 描述过于模糊 |
| 描述 > 100 字符 | 0（不扣分，仅标记） | 过长，建议拆分 |

分类标准：
- **精确**：评分 ≥ 80，无需优化
- **简略**：评分 40–79，可补充优化
- **模糊**：评分 < 40，需要重写

等待类步骤（含"等待"/"wait"/"加载"/"loading"关键词）特殊处理：
- 不适用"描述过于模糊"规则
- 额外检查：是否可替换为条件等待（如"等待某元素出现"）
- 若仅为固定时间等待（如"等待 3 秒"），标记为"建议替换为条件等待"

### 步骤 3：生成优化建议

AI 分析来源（按优先级）：

1. **读取 ui-tests 代码**：扫描 `$WORKDIR/ui-tests/src/pages/` 和 `$WORKDIR/ui-tests/src/components/` 中已有的 `aiTap`、`aiInput`、`aiAssert` 描述，提取元素描述模式
2. **读取开发代码库**：读取 `$WORKDIR/.claude/config/dev_repo.yml`（如存在）获取开发仓路径，扫描页面组件代码中的文本、aria-label、placeholder 等属性
3. **规则推断**：无法从代码库获取时，基于步骤动词和上下文推断，并在建议中标注"（规则推断，建议人工确认）"

补充规则：
- **输入操作**（含"输入"/"填写"/"键入"）：必须包含目标输入框的位置或占位符文本
- **点击操作**（含"点击"/"单击"/"双击"）：必须包含位置描述或元素视觉特征
- **等待操作**：检查是否可替换为条件等待（等待某元素出现/消失/变化）
- **模糊描述**（评分 < 40）：标记为"需要人工重写"，AI 仅提供参考建议

输出质量报告格式：

```
质量报告：<文件名>
————————————————————————————————
精确（≥80）：<N> 步  |  简略（40-79）：<M> 步  |  模糊（<40）：<K> 步

需优化步骤（<M+K> 个）：

[用例 <ID>] <用例标题>
  步骤 <序号>：<当前描述>
  问题：<问题标签列表>
  建议：<优化后描述>
  来源：<ai-code | dev-code | 规则推断>

...
```

若所有步骤评分 ≥ 80，输出：
```
✅ 该文件所有步骤质量良好，无需优化。
```

### 步骤 4：用户选择

用 `AskUserQuestion` 展示 4 个选项：

```
请选择操作：
  [1] 自动优化全部 —— 将所有建议直接写入文件
  [2] 逐个确认优化 —— 每个建议单独确认
  [3] 仅查看报告，不修改
  [4] 导出优化建议到文件 —— 保存到 testing/ui-testcases/enhance-report-<日期>.md
```

**选 [2] 时**，逐个展示每条建议并询问：
```
[用例 <ID>] 步骤 <序号>
  当前：<当前描述>
  建议：<优化后描述>
  来源：<来源>

  [1] 应用建议  [2] 手动修改  [3] 跳过  [4] 应用剩余全部
```
- 选 [2] 时，提示用户输入自定义描述后写入
- 选 [4] 时，对剩余步骤全部自动应用 AI 建议

**选 [3] 时**，不修改任何文件，仅展示报告后结束。

**选 [4] 时**，将质量报告写入 `$WORKDIR/testing/ui-testcases/enhance-report-<YYYY-MM-DD>.md`，不修改 YAML 文件。

### 步骤 5：回写 YAML

对每个被优化的文件执行以下操作：

1. 更新 `cases[*].steps[*].action` 字段为优化后的描述
2. 在文件头部 `metadata` 中更新或新增以下字段：
   ```yaml
   metadata:
     last_enhanced: <YYYY-MM-DD>
     enhanced_steps: [<用例ID>/<步骤序号>, ...]
   ```
   - `last_enhanced`：本次优化日期
   - `enhanced_steps`：记录被修改的步骤索引列表（格式 `<用例ID>/<步骤序号>`，如 `UI-CHAT-001/2`）

注意：
- 不修改评分 ≥ 80 的步骤
- 保留用户之前手动修改的步骤（通过 `enhanced_steps` 历史记录识别，若该步骤已在列表中则跳过自动优化，优先提示用户确认）
- 无法确定建议质量时，标注"（规则推断，建议人工确认）"并在选 [2] 逐个确认时特别提示

### 步骤 6：输出确认

写入完成后展示结果摘要：

```
✅ 优化完成！

· 处理文件：<N> 个
· 扫描步骤：<总步骤数> 步
· 优化步骤：<M> 步（精确 <a> | 简略 <b> | 模糊 <c> → 优化 <M>）
· 跳过步骤：<K> 步（已精确或用户跳过）

修改详情：
  · <文件名>：优化 <N> 步（步骤 <序号列表>）
  ...

下一步建议：
1. 审查优化后的文件，确认描述符合实际 UI 布局
2. 运行 UI 自动化测试验证用例可执行：/ui-automation --from-yaml <文件路径>
3. 如有遗漏，可重新运行 /testcase-ui-enhance 补充优化
```

## 注意事项

- 不修改评分 ≥ 80 的步骤，避免过度优化
- 等待类步骤特殊处理，不适用"描述过于模糊"扣分规则
- **环境操作/测试钩子步骤特殊处理**：包含以下关键词的步骤属于测试环境操作，不适用元素特征相关扣分（不含元素类型、不含位置上下文、不含视觉特征）：
  - `模拟`（模拟网络中断、模拟断网、模拟超时）
  - `触发`（触发错误、触发异常）
  - `跳转 URL`（直接 URL 跳转操作）
  - `构造`（构造错误协议块、构造请求）
  - `设置`（设置环境变量、设置配置）
  - 这类步骤无法也不应该补充 UI 元素特征，评分时跳过元素特征检查，避免误报为"模糊步骤"
- 保留用户之前手动修改的步骤（通过 `enhanced_steps` 历史记录识别）
- 无法从代码库获取信息时，降级为规则推断并在建议中标注"（规则推断，建议人工确认）"
- 模糊描述（评分 < 40）的步骤，AI 提供参考建议但建议人工确认后再写入
- `index.yml` 文件始终排除在扫描范围之外，不作为处理目标
