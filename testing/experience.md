## 常见测试模板

### 登录/认证类功能
- 正常：正确凭据登录、记住密码、自动登录
- 异常：错误密码、不存在账号、未激活账号、账号被锁定
- 边界：密码最短/最长、邮箱格式边界、特殊字符
- 安全：SQL 注入、XSS、防暴力破解（3次锁定）、token 过期
- 性能：并发登录、弱网登录
- 兼容：多端登录、多账号切换

### 列表/搜索类功能
- 正常：加载列表、分页、排序、筛选、搜索
- 异常：空列表、网络异常、搜索无结果
- 边界：单条数据、大数据量（1000+）、搜索关键词边界
- 性能：首屏加载时间、滚动流畅度

### 表单/配置类功能
- 正常：填写并提交、保存草稿
- 异常：必填项为空、格式错误、提交失败
- 边界：字段长度边界、特殊字符、Emoji
- 安全：XSS 注入、权限校验

### UI 自动化环境/启动类（2026-06-24 沉淀）
- 服务启动顺序：control-plane(2130) 必须最先起（认证后端，前端登录要连它）→ 前端 Web(1520) → 人工登录 → API(2126)。API 启动强依赖前端登录产生的 runtimeAuthUserId（require_authenticated_runtime_user_scope，guest 时直接 exit 1），顺序写反会死锁
- 登录态真相源：dev 模式下登录态在**前端 localStorage** 的 `caiclaw:desktop.config → runtimeAuth.userId`，**不在**磁盘 `desktop-client-config.json`（dev 模式通常不生成）。判断"是否已登录"应以测试实际注入的 `.auth-state.json`（npm run auth 快照，含该 localStorage）为准，与 fixture 用的认证来源保持一致
- 认证过期的隐蔽性：cookie/登录态失效时应用弹登录弹窗遮挡全屏，AI 定位会"假成功"（点在弹窗上），白跑数分钟后才在断言处误失败（如 `expected 0 to be greater than 0`）。fixture 应加**登录态前置检查**：进页面后检测登录弹窗，命中即秒级 fail 并提示重新 `npm run auth`
- AI 回复完成判断：用"消息长度趋于稳定"而非"两次提取文本完全相等"——aiQuery 提取文本每次有细微抖动，严格相等几乎不成立，会一直等到超时兜底
- Shell 脚本路径：在 `cd` 切换工作目录**之前**用 `BASH_SOURCE` 解析脚本目录并定位相对资源（如 .auth-state.json），否则 cd 后相对路径会算错
- 排查顺序：测试失败先分清"环境问题 vs 代码问题"——查端口存活、查失败截图（常能一眼看出登录弹窗/空白页），再看 fallback-events.log 是否触发 AI 降级
